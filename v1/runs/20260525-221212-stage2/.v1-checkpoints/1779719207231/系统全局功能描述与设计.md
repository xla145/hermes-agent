## 2. 系统边界与业务闭环

### 2.1 系统边界

**系统负责范围：**
- 农产品全流程溯源信息录入、审核、查询与管理
- 实时现货交易全流程（挂单-撮合-下单-交割-结算）
- 三端界面开发与交互（大屏/PC/移动端）
- 与溯源/仓储/物流/支付/监管等外部系统的模拟对接
- 主体准入审核与账户管理
- 资金结算与对账管理
- 监管数据展示与异常预警

**不包含范围：**
- 真实区块链节点部署（模拟展示）
- 真实物联网设备接入（模拟数据）
- 真实支付渠道对接（模拟支付）
- 真实仓储/物流系统对接（模拟接口）
- 微信小程序实际开发（原型展示）
- 完整运营计划与盈利模式
- 长期运维系统

### 2.2 核心业务闭环

**闭环1：溯源管理闭环**
```
产地信息录入 → 加工信息录入 → 仓储信息录入 → 运输信息录入 → 交易交割信息 → 溯源档案生成 → 扫码查询
```

**闭环2：交易流程闭环**
```
主体准入 → 账户开户 → 保证金缴纳 → 挂单发布 → 撮合下单 → 交割验收 → 资金结算 → 对账确认 → 售后服务
```

**闭环3：监管闭环**
```
数据采集 → 实时展示 → 异常预警 → 监管指令 → 执行反馈 → 统计报表
```

## 4. 全局业务场景

### 场景1：商户挂单发布

- **场景目标**：商户发布农产品现货挂单，审核后公开展示
- **参与角色**：商户（卖方）、平台运营（审核）
- **触发条件**：商户有现货待售，登录平台发布挂单
- **前置条件**：商户已完成主体准入审核、账户开户和溯源账户绑定
- **核心流程**：
  1. 商户登录平台，进入挂单模块
  2. 填写挂单信息（品种/等级/规格/数量/单价/交货地点/时间）
  3. 上传实物图片和检测报告（可选）
  4. 提交平台审核
  5. 审核通过后挂单公开展示，有效期最长48小时
- **分支流程**：
  - 审核不通过：修改后重新提交
  - 超时未售：自动下架，可重新发布
- **异常流程**：
  - 库存不足：阻止挂单或自动下架
  - 价格异常：触发预警，人工复核
- **涉及功能**：挂单发布、挂单审核、挂单查询、库存校验
- **涉及页面**：挂单发布页、挂单列表页、挂单详情页
- **涉及数据对象**：挂单信息、农产品信息、库存信息
- **输出结果**：挂单信息发布，采购商可见
- **闭环检查**：完整
- **来源/依据**：用户明确

### 场景2：采购商下单交易

- **场景目标**：采购商筛选挂单并完成下单，保证金冻结
- **参与角色**：采购商（买方）、商户（卖方）、平台系统
- **触发条件**：采购商有采购需求，浏览到满足条件的挂单
- **前置条件**：采购商已完成主体准入、支付账户绑定、保证金账户有足够余额
- **核心流程**：
  1. 采购商通过多维度筛选（品种/规格/价格/产地）查找挂单
  2. 查看挂单详情及溯源信息，选择撮合方式
  3. 提交下单申请
  4. 平台生成标准化电子交易订单，双方在线确认
  5. 平台自动冻结双方对应保证金
  6. 订单生效，进入交割准备阶段
- **分支流程**：
  - 自主撮合：买卖双方直接确认
  - 平台匹配：系统智能推荐匹配
  - 批量撮合：多笔订单批量处理
- **异常流程**：
  - 保证金不足：提示充值，无法下单
  - 库存不足：自动锁定或取消订单
- **涉及功能**：挂单查询、撮合匹配、下单生成、保证金冻结
- **涉及页面**：挂单列表页、挂单详情页、下单确认页、订单列表页
- **涉及数据对象**：交易订单、保证金账户、挂单信息
- **输出结果**：订单生效，保证金冻结
- **闭环检查**：完整
- **来源/依据**：用户明确

### 场景3：农产品交割验收

- **场景目标**：买卖双方完成实物交割，验收确认
- **参与角色**：商户（卖方）、采购商（买方）、平台监督
- **触发条件**：订单生效后，交割时间到达
- **前置条件**：卖方已完成货物准备和溯源二维码粘贴；买方已准备货款和验收人员
- **核心流程**：
  1. 卖方按订单要求准备货物，上传交割准备凭证
  2. 卖方将农产品送达指定交割地点
  3. 买方到场验收，扫描溯源二维码核对信息
  4. 提交验收结果（合格/不合格）
  5. 验收合格：双方在线签字确认，触发货款结算流程
  6. 验收不合格：买方提交异议及证据，平台24小时内介入处理
- **分支流程**：
  - 验收合格：进入结算流程
  - 验收不合格：进入纠纷处理流程
- **异常流程**：
  - 卖方未按时送达：违约处理
  - 买方拒绝验收：无正当理由视为违约
- **涉及功能**：交割管理、验收确认、异议提交、纠纷处理
- **涉及页面**：交割确认页、验收详情页、纠纷处理页
- **涉及数据对象**：交易订单、溯源档案、交割记录
- **输出结果**：交割确认单生成，进入结算流程或异常处理流程
- **闭环检查**：完整
- **来源/依据**：用户明确

### 场景4：全流程溯源查询

- **场景目标**：消费者/采购商/监管人员查询农产品全流程溯源信息
- **参与角色**：消费者/采购商/监管人员
- **触发条件**：需要了解农产品来源、质量和流转过程
- **前置条件**：溯源信息已录入并审核通过
- **核心流程**：
  1. 扫描农产品包装溯源二维码，或在平台输入溯源码/订单号
  2. 系统展示全环节溯源信息（产地/加工/仓储/运输/交易/交割）
  3. 可查看检测报告、交易记录、验收记录
  4. 支持按环节/时间/品种/主体多维度筛选
  5. 支持导出溯源记录
- **分支流程**：
  - 微信小程序扫码：跳转小程序展示
  - PC端查询：平台内直接展示
  - 监管批量查询：监管端批量导出
- **异常流程**：
  - 溯源码无效：提示查询不到信息
  - 信息不完整：展示已录入部分，标注缺失环节
- **涉及功能**：溯源查询、二维码生成、溯源审核
- **涉及页面**：溯源查询页、溯源详情页、溯源批量查询页
- **涉及数据对象**：溯源档案、农产品批次、检测报告
- **输出结果**：完整溯源档案展示
- **闭环检查**：完整
- **来源/依据**：用户明确

### 场景5：资金结算与对账

- **场景目标**：完成交割后资金结算，保证金退还
- **参与角色**：采购商（买方）、商户（卖方）、平台结算系统
- **触发条件**：交割验收合格，双方签字确认
- **前置条件**：买方账户有足够资金；交易双方无未解决纠纷
- **核心流程**：
  1. 平台通知买方支付货款
  2. 买方通过支持渠道（微信/支付宝/银行）支付
  3. 货款存入第三方监管账户（模拟）
  4. 平台核对无误，24小时内扣除0.5%~1%手续费后划转至卖方
  5. 平台自动解冻双方保证金
  6. 生成标准化对账单，双方在线核对，支持导出
  7. 卖方开具发票并上传平台
- **分支流程**：
  - 正常结算：按流程完成
  - 违约处理：扣除保证金赔偿守约方
- **异常流程**：
  - 支付失败：重新支付或取消订单
  - 结算异常：人工介入处理
- **涉及功能**：资金支付、保证金管理、结算划转、对账管理、发票管理
- **涉及页面**：支付页面、对账单页、结算记录页、发票管理页
- **涉及数据对象**：交易订单、保证金账户、结算记录、对账单
- **输出结果**：货款划转完成，保证金退还，对账单生成
- **闭环检查**：完整
- **来源/依据**：用户明确

### 场景6：监管大屏实时监管

- **场景目标**：监管人员在大屏端查看实时数据，发送监管指令
- **参与角色**：监管人员、平台系统
- **触发条件**：监管人员登录大屏端，或系统触发异常预警
- **前置条件**：监管人员已获得授权账号
- **核心流程**：
  1. 公众可查看基础数据（交易概况/行情走势/溯源动态）
  2. 监管人员登录后切换视图，查看详细数据和异常预警
  3. 点击异常数据卡片查看明细
  4. 发送监管指令（违规查处、品种管控等）
  5. 平台执行后反馈结果，形成监管-执行-反馈闭环
- **分支流程**：
  - 公开模式：仅展示基础数据
  - 监管模式：展示详细数据和预警
- **异常流程**：
  - 数据刷新失败：显示上次数据，标注刷新时间
  - 指令发送失败：提示重试
- **涉及功能**：数据可视化、异常预警、监管指令、统计报表
- **涉及页面**：监管大屏首页、交易概况页、溯源动态页、异常预警页
- **涉及数据对象**：交易数据、溯源数据、预警记录
- **输出结果**：监管指令执行，异常得到及时处置
- **闭环检查**：完整
- **来源/依据**：用户明确

### 场景7：主体准入审核

- **场景目标**：完成新主体入驻审核，开通交易权限
- **参与角色**：申请主体、平台运营人员
- **触发条件**：主体申请进入平台交易
- **前置条件**：申请主体已准备资质材料
- **核心流程**：
  1. 主体提交注册申请，上传资质材料
  2. 平台运营人员严格审核
  3. 审核通过：开通交易/服务权限，完成账户开户和支付/溯源账户绑定
  4. 审核失败：反馈原因，引导补充材料重新申请
- **分支流程**：
  - 审核通过：开通权限
  - 审核驳回：修改后重新提交
  - 补充材料：重新审核
- **异常流程**：
  - 资质造假：永久封禁，报警处理
  - 逾期未补充：申请过期
- **涉及功能**：注册申请、资质上传、审核管理、账户开户
- **涉及页面**：注册申请页、资质上传页、审核列表页、审核详情页
- **涉及数据对象**：用户主体、资质材料、账户信息
- **输出结果**：主体获得交易权限
- **闭环检查**：完整
- **来源/依据**：用户明确

### 5.5 权限与数据规则

#### 5.5.1 角色权限

| 角色 | 菜单权限 | 按钮权限 | 数据权限 |
| --- | :--- | :--- | :--- |
| 商户 | 溯源管理、挂单管理、订单管理、结算管理、我 | 发布挂单、录入溯源、查看订单、结算对账 | 仅自有数据 |
| 采购商 | 挂单查询、交易下单、交割验收、溯源查询、订单管理 | 下单、验收确认、溯源查询 | 仅自有数据 |
| 监管人员 | 监管大屏、数据监控、主体监管、质量监管 | 查看数据、导出报表、发送预警 | 全局只读 |

#### 5.5.2 菜单权限

- 商户：交易管理（挂单）、溯源管理、订单管理、结算管理、个人中心
- 采购商：交易管理（挂单查询）、订单管理、溯源查询、个人中心
- 监管人员：监管中心（公开）、监管中心（监管模式）
- 平台运营：全部一级菜单

#### 5.5.3 按钮权限

- 商户：挂单发布、挂单编辑、挂单撤销、溯源录入、订单查看、结算对账
- 采购商：下单、确认收货、验收提交、溯源查询
- 监管人员：数据导出、预警发送
- 平台运营：新增、编辑、删除、审核、导出

#### 5.5.4 数据权限

- 商户、采购商：仅可见自己创建的数据
- 监管人员：可见全部数据，仅供查看
- 平台运营：可见全部数据，可操作
