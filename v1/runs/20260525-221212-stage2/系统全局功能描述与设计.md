### 2.4 核心业务闭环

#### 闭环1：挂单-交易闭环
```
商户发布挂单 → 平台审核 → 挂单展示 → 采购商筛选 → 下单申请 → 双方确认 → 保证金冻结 → 订单生效
```

#### 闭环2：交割-结算闭环
```
卖方准备货物 → 送达交割点 → 买方验收 → 双方签字确认 → 货款支付 → 平台划转 → 保证金退还 → 对账生成
```

#### 闭环3：溯源闭环
```
产地录入 → 加工录入 → 仓储录入 → 运输录入 → 交易记录 → 交割确认 → 溯源档案生成 → 查询验证
```

#### 闭环4：监管闭环
```
数据采集 → 实时展示 → 异常预警 → 监管介入 → 指令下达 → 执行反馈 → 记录留存
```

## 4. 全局业务场景

### 场景1：商户挂单发布

- 场景目标：商户发布农产品现货挂单，进入市场交易
- 参与角色：商户（卖方）、平台运营（审核）
- 触发条件：商户有现货待售，登录平台发布挂单
- 前置条件：商户已完成主体准入审核、账户开户和溯源账户绑定
- 核心流程：
  1. 商户登录平台，进入挂单模块
  2. 填写挂单信息（品种/等级/规格/数量/单价/交货地点/时间）
  3. 上传实物图片和检测报告（可选）
  4. 提交平台审核
  5. 审核通过后挂单公开展示，有效期最长48小时
- 分支流程：
  - 审核驳回：修改后重新提交
  - 超时未售：自动下架，可重新发布
- 异常流程：
  - 库存不足：禁止发布或自动调整数量
  - 资质过期：提示更新资质后再发布
- 涉及功能：挂单发布、挂单审核、挂单展示、库存校验
- 涉及页面：挂单列表、挂单发布、挂单详情、挂单审核
- 涉及数据对象：挂单信息、用户主体、农产品批次
- 输出结果：挂单信息发布，采购商可见，超时自动下架
- 闭环检查：完整
- 来源/依据：用户明确

### 场景2：采购商下单交易

- 场景目标：采购商完成下单操作，生成有效订单
- 参与角色：采购商（买方）、商户（卖方）、平台系统
- 触发条件：采购商有采购需求，浏览到满足条件的挂单
- 前置条件：采购商已完成主体准入、支付账户绑定、保证金账户有足够余额
- 核心流程：
  1. 采购商通过多维度筛选（品种/规格/价格/产地）查找挂单
  2. 查看挂单详情及溯源信息，选择撮合方式（自主/平台匹配/批量）
  3. 提交下单申请
  4. 平台生成标准化电子交易订单，双方在线确认
  5. 平台自动冻结双方对应保证金
  6. 订单生效，进入交割准备阶段
- 分支流程：
  - 商户不确认：订单挂起，24小时后自动取消
  - 保证金不足：提示充值后重新确认
- 异常流程：
  - 库存不足：提示挂单已售罄
  - 价格变动：提示价格已调整，需重新下单
- 涉及功能：挂单查询、撮合下单、订单生成、保证金冻结
- 涉及页面：挂单列表、挂单详情、下单确认、订单详情
- 涉及数据对象：交易订单、挂单信息、保证金账户
- 输出结果：订单生效，保证金冻结，双方收到消息提醒
- 闭环检查：完整
- 来源/依据：用户明确

### 场景3：农产品交割验收

- 场景目标：完成农产品实物交割，双方确认验收结果
- 参与角色：商户（卖方）、采购商（买方）、平台监督（模拟）
- 触发条件：订单生效后，交割时间到达
- 前置条件：卖方已完成货物准备和溯源二维码粘贴；买方已准备货款和验收人员
- 核心流程：
  1. 卖方按订单要求准备货物，上传交割准备凭证
  2. 卖方将农产品送达指定交割地点
  3. 买方到场验收，扫描溯源二维码核对信息
  4. 提交验收结果（合格/不合格）
  5. 验收合格：双方在线签字确认，触发货款结算流程
  6. 验收不合格：买方提交异议及证据，平台24小时内介入处理
- 分支流程：
  - 验收合格：进入结算流程
  - 验收不合格：进入纠纷处理流程
- 异常流程：
  - 卖方未按时送达：违约处理，保证金扣除
  - 买方拒不验收：平台介入，按默认合格处理
  - 双方分歧：平台仲裁，扣除违约方保证金
- 涉及功能：交割准备、溯源核对、验收确认、异常处理
- 涉及页面：订单详情、交割确认、验收提交、纠纷处理
- 涉及数据对象：交易订单、溯源档案、交割记录
- 输出结果：交割确认单生成，溯源信息完善，进入结算流程或异常处理流程
- 闭环检查：完整
- 来源/依据：用户明确

### 场景4：全流程溯源查询

- 场景目标：查询农产品全流程溯源信息
- 参与角色：消费者/采购商/监管人员
- 触发条件：需要了解农产品来源、质量和流转过程
- 前置条件：溯源信息已录入并审核通过
- 核心流程：
  1. 扫描农产品包装溯源二维码，或在平台输入溯源码/订单号
  2. 系统展示全环节溯源信息（产地/加工/仓储/运输/交易/交割）
  3. 可查看检测报告、交易记录、验收记录
  4. 支持按环节/时间/品种/主体多维度筛选
  5. 支持导出溯源记录
- 分支流程：
  - 溯源码无效：提示无法查询
  - 部分环节缺失：展示已录入信息，标注缺失环节
- 异常流程：
  - 溯源信息被篡改：显示异常警告
  - 超过保存期限：提示已超过查询时限
- 涉及功能：溯源查询、二维码解析、多维度筛选、导出
- 涉及页面：溯源查询（大屏）、溯源查询（PC）、溯源查询（移动端/小程序）
- 涉及数据对象：溯源档案、农产品批次、检测报告
- 输出结果：完整溯源档案展示，数据可信、不可篡改（区块链模拟）
- 闭环检查：完整
- 来源/依据：用户明确

### 场景5：资金结算与对账

- 场景目标：完成交易资金结算，生成对账凭证
- 参与角色：采购商（买方）、商户（卖方）、平台结算系统
- 触发条件：交割验收合格，双方签字确认
- 前置条件：买方账户有足够资金；交易双方无未解决纠纷
- 核心流程：
  1. 平台通知买方支付货款
  2. 买方通过支持渠道（微信/支付宝/银行）支付
  3. 货款存入第三方监管账户（模拟）
  4. 平台核对无误，24小时内扣除0.5%~1%手续费后划转至卖方
  5. 平台自动解冻双方保证金
  6. 生成标准化对账单，双方在线核对，支持导出
  7. 卖方开具发票并上传平台
- 分支流程：
  - 买方逾期未付款：扣除保证金，订单取消
  - 卖方拒开发票：平台督促，限制后续交易
- 异常流程：
  - 支付失败：提示更换支付方式
  - 银行转账超时：人工介入处理
- 涉及功能：货款支付、费用扣除、保证金退还、对账生成、发票上传
- 涉及页面：订单详情、支付页面、对账页面、发票管理
- 涉及数据对象：结算记录、保证金账户、发票记录
- 输出结果：货款划转完成，保证金退还，对账单生成，凭证留存≥3年
- 闭环检查：完整
- 来源/依据：用户明确

### 场景6：监管大屏实时监管

- 场景目标：监管部门实时掌握市场动态，及时发现和处理异常
- 参与角色：监管人员、平台系统
- 触发条件：监管人员登录大屏端，或系统触发异常预警
- 前置条件：监管人员已获得授权账号
- 核心流程：
  1. 公众可查看基础数据（交易概况/行情走势/溯源动态）
  2. 监管人员登录后切换视图，查看详细数据和异常预警
  3. 点击异常数据卡片查看明细
  4. 发送监管指令（违规查处、品种管控等）
  5. 平台执行后反馈结果，形成监管-执行-反馈闭环
- 分支流程：
  - 预警等级较低：自动记录，定期处理
  - 预警等级较高：立即通知，限时处理
- 异常流程：
  - 数据加载失败：显示上次缓存数据，标注更新时间
  - 指令发送失败：提示重试，人工电话通知
- 涉及功能：数据可视化、实时预警、监管指令、统计分析
- 涉及页面：大屏首页、交易监管、溯源监管、预警中心、指令管理
- 涉及数据对象：交易数据、溯源数据、预警记录、监管指令
- 输出结果：监管指令执行，异常得到及时处置
- 闭环检查：完整
- 来源/依据：用户明确

### 场景7：主体准入审核

- 场景目标：完成新主体资质审核，开通交易权限
- 参与角色：申请主体（商户/采购商）、平台运营人员
- 触发条件：主体申请进入平台交易
- 前置条件：申请主体已准备资质材料（营业执照、食品经营许可证等）
- 核心流程：
  1. 主体提交注册申请，上传资质材料
  2. 平台运营人员严格审核
  3. 审核通过：开通交易/服务权限，完成账户开户和支付/溯源账户绑定
  4. 审核失败：反馈原因，引导补充材料重新申请
- 分支流程：
  - 资质不全：驳回补充
  - 资质过期：提醒更新
  - 违规记录：拒绝准入
- 异常流程：
  - 审核超时：自动提醒，48小时未审核自动通过
  - 申诉处理：对审核结果不满意，可提交申诉
- 涉及功能：注册申请、资质上传、审核管理、账户开通
- 涉及页面：注册申请、资质填写、审核列表、审核详情、账户管理
- 涉及数据对象：用户主体、资质材料、账户信息
- 输出结果：主体获得交易权限，可进行挂单/下单操作
- 闭环检查：完整
- 来源/依据：用户明确
