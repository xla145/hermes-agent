## 4. 场景与诉求分析

### 场景 1：商户挂单发布

- 场景描述：商户登录移动端或PC端，发布农产品现货挂单，包含品种、规格、价格、质量信息等。
- 参与角色：商户（卖方）、平台运营（审核）
- 触发条件：商户有现货待售，登录平台发布挂单
- 前置条件：商户已完成主体准入审核、账户开户和溯源账户绑定
- 场景流程：
  1. 商户登录平台，进入挂单模块
  2. 填写挂单信息（品种/等级/规格/数量/单价/交货地点/时间）
  3. 上传实物图片和检测报告（可选）
  4. 提交平台审核
  5. 审核通过后挂单公开展示，有效期最长48小时
- 输出结果：挂单信息发布，采购商可见，超时自动下架
- 闭环检查：完整
- 相关诉求：支持100+ SKU标准化挂单，支持编辑、撤销；库存自动校验防止超卖
- 来源/依据：用户明确

### 场景 2：采购商下单交易

- 场景描述：采购商在平台筛选挂单，查看溯源信息，提交下单申请，完成保证金冻结。
- 参与角色：采购商（买方）、商户（卖方）、平台系统
- 触发条件：采购商有采购需求，浏览到满足条件的挂单
- 前置条件：采购商已完成主体准入、支付账户绑定、保证金账户有足够余额
- 场景流程：
  1. 采购商通过多维度筛选（品种/规格/价格/产地）查找挂单
  2. 查看挂单详情及溯源信息，选择撮合方式（自主/平台匹配/批量）
  3. 提交下单申请
  4. 平台生成标准化电子交易订单，双方在线确认
  5. 平台自动冻结双方对应保证金
  6. 订单生效，进入交割准备阶段
- 输出结果：订单生效，保证金冻结，双方收到消息提醒
- 闭环检查：完整
- 相关诉求：支持在线沟通、订单异议修改、消息提醒
- 来源/依据：用户明确

### 场景 3：农产品交割验收

- 场景描述：卖方送达货物，买方按标准验收，扫描溯源二维码核对，双方在线签字确认。
- 参与角色：商户（卖方）、采购商（买方）、平台监督（模拟）
- 触发条件：订单生效后，交割时间到达
- 前置条件：卖方已完成货物准备和溯源二维码粘贴；买方已准备货款和验收人员
- 场景流程：
  1. 卖方按订单要求准备货物，上传交割准备凭证
  2. 卖方将农产品送达指定交割地点
  3. 买方到场验收，扫描溯源二维码核对信息
  4. 提交验收结果（合格/不合格）
  5. 验收合格：双方在线签字确认，触发货款结算流程
  6. 验收不合格：买方提交异议及证据，平台24小时内介入处理
- 输出结果：交割确认单生成，溯源信息完善，进入结算流程或异常处理流程
- 闭环检查：完整
- 相关诉求：异常处理机制明确，责任划分清晰，证据留存
- 来源/依据：用户明确

### 场景 4：全流程溯源查询

- 场景描述：消费者、采购商或监管人员扫描溯源二维码或通过平台，查看农产品从产地到交割的全环节溯源信息。
- 参与角色：消费者/采购商/监管人员
- 触发条件：需要了解农产品来源、质量和流转过程
- 前置条件：溯源信息已录入并审核通过
- 场景流程：
  1. 扫描农产品包装溯源二维码，或在平台输入溯源码/订单号
  2. 系统展示全环节溯源信息（产地/加工/仓储/运输/交易/交割）
  3. 可查看检测报告、交易记录、验收记录
  4. 支持按环节/时间/品种/主体多维度筛选
  5. 支持导出溯源记录
- 输出结果：完整溯源档案展示，数据可信、不可篡改（区块链模拟）
- 闭环检查：完整
- 相关诉求：无需下载APP，微信小程序可查；监管部门支持批量查询
- 来源/依据：用户明确

### 场景 5：资金结算与对账

- 场景描述：交割验收合格后，买方支付货款，平台核对后划转至卖方账户，双方保证金解冻退还，生成对账单。
- 参与角色：采购商（买方）、商户（卖方）、平台结算系统
- 触发条件：交割验收合格，双方签字确认
- 前置条件：买方账户有足够资金；交易双方无未解决纠纷
- 场景流程：
  1. 平台通知买方支付货款
  2. 买方通过支持渠道（微信/支付宝/银行）支付
  3. 货款存入第三方监管账户（模拟）
  4. 平台核对无误，24小时内扣除0.5%~1%手续费后划转至卖方
  5. 平台自动解冻双方保证金
  6. 生成标准化对账单，双方在线核对，支持导出
  7. 卖方开具发票并上传平台
- 输出结果：货款划转完成，保证金退还，对账单生成，凭证留存≥3年
- 闭环检查：完整
- 相关诉求：违约处理流程清晰，资金安全有保障
- 来源/依据：用户明确

### 场景 6：监管大屏实时监管

- 场景描述：监管人员在大屏端查看实时交易概况、溯源动态、异常预警，必要时发送监管指令。
- 参与角色：监管人员、平台系统
- 触发条件：监管人员登录大屏端，或系统触发异常预警
- 前置条件：监管人员已获得授权账号
- 场景流程：
  1. 公众可查看基础数据（交易概况/行情走势/溯源动态）
  2. 监管人员登录后切换视图，查看详细数据和异常预警
  3. 点击异常数据卡片查看明细
  4. 发送监管指令（违规查处、品种管控等）
  5. 平台执行后反馈结果，形成监管-执行-反馈闭环
- 输出结果：监管指令执行，异常得到及时处置
- 闭环检查：完整
- 相关诉求：数据自动刷新（5分钟/次），支持手动刷新；数据可视化清晰
- 来源/依据：用户明确

### 场景 7：主体准入审核

- 场景描述：新商户/采购商/配套机构提交注册申请和资质材料，平台运营人员审核通过后开通交易权限。
- 参与角色：申请主体、平台运营人员
- 触发条件：主体申请进入平台交易
- 前置条件：申请主体已准备资质材料（营业执照、食品经营许可证等）
- 场景流程：
  1. 主体提交注册申请，上传资质材料
  2. 平台运营人员严格审核
  3. 审核通过：开通交易/服务权限，完成账户开户和支付/溯源账户绑定
  4. 审核失败：反馈原因，引导补充材料重新申请
- 输出结果：主体获得交易权限，可进行挂单/下单操作
- 闭环检查：完整
- 相关诉求：支持审核状态查询、保证金缴纳和授信管理
- 来源/依据：用户明确

## 9. 风险点与关注点

### 风险点 1：Demo范围边界不清晰

- 风险描述：需求文档内容极为丰富，涉及三端（大屏/PC/移动端）+ 四大模块 + 六类外部系统对接，Demo范围边界若不清晰，可能导致开发工作量失控。
- 影响范围：开发排期、验收标准
- 风险等级：高
- 应对策略：按模块优先级明确Demo核心功能清单，非核心功能以静态展示或模拟数据替代
- 来源/依据：模型推理

### 风险点 2：外部系统对接模拟实现复杂度

- 风险描述：与溯源/仓储/物流/支付/监管/检测/金融系统均为模拟对接，模拟接口设计不当可能影响业务流程完整性演示。
- 影响范围：系统对接模块、演示效果
- 风险等级：中
- 应对策略：使用Mock数据和模拟接口，设计清晰的模拟对接展示界面，明确标注"模拟"字样
- 来源/依据：用户明确（文档已标注模拟对接）

### 风险点 3：小规模农户操作门槛

- 风险描述：小规模农户/个体商户操作能力有限，系统若不够简化，可能造成实际使用困难。
- 影响范围：移动端用户体验、系统推广
- 风险等级：中
- 应对策略：移动端核心操作≤3步；提供模板化录入；内置操作指引；支持拍照识别
- 来源/依据：用户明确

### 风险点 4：资金安全合规风险

- 风险描述：Demo涉及保证金冻结/退还/货款划转等资金操作，虽为模拟，但流程展示需符合监管要求，避免产生合规误导。
- 影响范围：结算模块、监管验收
- 风险等级：高
- 应对策略：资金操作界面明确标注"Demo演示，非真实资金"；资金操作流程严格按需求文档规范展示
- 来源/依据：模型推理

### 风险点 5：多端数据同步一致性

- 风险描述：大屏/PC/移动端数据需实时同步，Demo中若出现数据不一致，影响演示可信度。
- 影响范围：所有业务模块、演示效果
- 风险等级：中
- 应对策略：Demo使用统一Mock数据源，确保多端展示数据一致
- 来源/依据：行业经验补充

### 风险点 6：区块链和物联网技术模拟深度

- 风险描述：需求要求区块链存储（溯源不可篡改）和物联网采集（温湿度/GPS），Demo为模拟实现，展示深度不足可能影响监管部门的可信度。
- 影响范围：溯源体系展示效果
- 风险等级：低
- 应对策略：在界面中展示"区块链存证"标识和"物联网实时采集"效果，使用动态模拟数据增强真实感
- 来源/依据：模型推理

### 风险点 7：数据安全合规风险

- 风险描述：Demo涉及用户信息、交易数据、溯源数据等敏感信息，需符合《个人信息保护法》《数据安全法》要求。
- 影响范围：用户数据、合规性
- 风险等级：高
- 应对策略：Demo使用完全模拟数据；敏感字段（手机号/银行卡/身份证）脱敏展示；提供隐私政策展示入口
- 来源/依据：用户明确（法规引用）
