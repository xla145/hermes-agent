## 2. 页面目标与使用场景

* 页面目标：完成身份认证和角色分流。
* 使用场景：用户在“全局入口”中进入本页面，完成“登录表单、安全提示、错误锁定、跳转”相关操作。
* 触发入口：来自无、菜单入口、消息提醒、待办卡片或业务详情跳转。
* 输出结果：形成可查询、可追溯、可流转的业务数据，并通过消息/状态/日志反馈给相关角色。

## 9. 交互逻辑

### 9.1 页面初始化

* 默认展示：按角色加载可见菜单、快捷操作和最近业务数据；列表页默认展示最近30天数据；详情页按ID加载详情。
* 默认筛选：状态优先展示待处理/进行中数据，时间范围默认近30天。
* 默认排序：按更新时间倒序，异常/待处理数据置顶。
* 默认状态：若无明确状态，采用“正常/待处理”作为默认状态。
* 初始化异常：接口失败时显示加载失败卡片，可点击重试；大屏保留上次缓存数据并标注更新时间。

### 9.2 查询与筛选

* 筛选项：关键词、状态、时间范围、主体/品类/订单号等与用户账号、登录日志相关字段。
* 查询规则：点击查询后刷新数据；回车触发关键词搜索；多条件为AND关系。
* 重置规则：清空筛选项并恢复默认时间范围和默认状态。
* 无结果状态：显示“暂无符合条件的数据”，提供重置筛选或新增入口（如有权限）。
* 查询异常：提示“查询失败，请稍后重试”，记录接口日志。

### 9.3 新增/编辑/删除/提交

* 新增逻辑：有新增能力时展示主按钮，进入表单后支持保存草稿和正式提交。
* 编辑逻辑：仅允许在草稿、驳回、待处理等可编辑状态操作；已完成/已归档数据默认只读。
* 删除逻辑：生产业务数据原则上不物理删除，仅支持撤销、停用、作废并留痕。
* 提交逻辑：提交前进行必填、格式、状态、权限和重复提交校验；关键操作弹出二次确认。
* 校验规则：必填字段不能为空；金额/数量必须大于0；日期不得早于业务开始时间；附件格式和大小受限。
* 重复提交处理：提交按钮Loading并禁用，接口返回后恢复；重复请求提示“请勿重复提交”。

### 9.4 详情与跳转

* 详情入口：列表行、卡片、消息、预警、待办均可进入详情。
* 跳转目标：依据业务流转跳转到无、关联订单、溯源档案、支付、交割、纠纷或日志页面。
* 返回规则：返回时保留来源页查询条件、分页和滚动位置。
* 面包屑规则：一级模块 > 页面名称 > 详情/操作，隐藏路由不在侧边栏显示。

## 12. 异常、空状态和边界场景

| 场景   | 触发条件 | 页面表现 | 用户操作 | 恢复方式 |
| ---- | ---- | ---- | ---- | ---- |
| 空数据  | 首次进入或筛选无结果 | 空状态插图+提示文案 | 重置筛选/新增数据 | 恢复默认查询或完成新增 |
| 无权限  | 角色无菜单/按钮/数据权限 | 403提示+返回工作台 | 返回首页/联系管理员 | 管理员授权后重试 |
| 加载失败 | 接口超时或网络异常 | 错误卡片+重试按钮 | 点击重试 | 接口恢复或使用缓存数据 |
| 提交失败 | 校验失败或服务异常 | 表单错误提示/Toast | 修正字段后重提 | 通过校验后提交 |
| 数据冲突 | 多人同时修改或状态已变化 | 弹窗提示“数据已更新” | 刷新详情 | 获取最新数据后再操作 |
| 状态异常 | 非法状态流转或业务规则不满足 | 红色Alert说明原因 | 返回/联系运营 | 运营处理或系统修复 |

## 15. 原型生成说明

* 页面布局建议：PC端采用顶部导航+左侧菜单+内容区；移动端采用顶部标题+内容区+底部导航；大屏按1920×1080看板布局；小程序使用轻量查询与结果卡片。
* 关键交互优先级：优先表达“登录、找回密码、角色跳转”和状态流转，其次表达筛选、导出、详情、异常反馈。
* 需要重点表达的业务逻辑：页面需体现F006对应功能、正常、失败、锁定状态标签、角色权限差异和数据留痕。
* 可使用模拟数据：使用广西贵港本地农产品、商户、订单、溯源码、监管预警等Mock数据；敏感字段脱敏。
* 需要避免的原型误差：不得表现为真实资金交易、真实外部接口或真实区块链/物联网；模拟能力必须显著标注“Demo模拟”。
