## 2. 系统边界与业务闭环

### 2.1 系统边界

- **系统负责范围**：
  - 农产品全流程溯源信息录入、查询、审核与预警
  - 实时现货交易全流程（挂单-撮合-下单-交割-结算）
  - 大屏端数据可视化展示
  - PC端管理后台（商户/采购商/运营/监管）
  - 移动端商户/采购商/监管功能
  - 与溯源/仓储/物流/支付/监管系统的模拟对接

- **不包含范围**：
  - 真实区块链节点部署（区块链功能模拟展示）
  - 真实物联网设备接入（物联网数据模拟）
  - 真实支付系统对接（支付功能模拟）
  - 真实外部系统直连（均为Demo模拟对接）
  - 完整运营计划、盈利模式和长期运维功能

### 2.2 核心业务闭环

```
挂单发布 → 撮合匹配 → 下单成交 → 交割验收 → 资金结算 → 溯源归档
     ↑                                              ↓
     └──────────────────────────────────────────────┘
```

1. **交易闭环**：商户挂单 → 采购商下单 → 保证金冻结 → 交割验收 → 货款结算 → 保证金退还
2. **溯源闭环**：产地录入 → 加工录入 → 仓储录入 → 运输录入 → 交易交割 → 扫码查询
3. **监管闭环**：数据展示 → 异常预警 → 监管指令 → 执行反馈 → 记录归档

## 4. 全局业务场景

### 场景 1：商户挂单发布

- **场景目标**：商户发布农产品现货挂单，审核通过后公开展示
- **参与角色**：商户（卖方）、平台运营（审核）
- **触发条件**：商户有现货待售，登录平台发布挂单
- **前置条件**：商户已完成主体准入审核、账户开户和溯源账户绑定
- **核心流程**：
  1. 商户登录平台，进入挂单模块
  2. 填写挂单信息（品种/等级/规格/数量/单价/交货地点/时间）
  3. 上传实物图片和检测报告（可选）
  4. 提交平台审核
  5. 审核通过后挂单公开展示，有效期最长48小时
- **分支流程**：挂单审核驳回 → 商户修改后重新提交
- **异常流程**：库存不足、资质过期、价格异常
- **涉及功能**：挂单操作、挂单审核、库存校验、有效期管理
- **涉及页面**：挂单发布页、挂单列表页、挂单详情页、挂单审核页
- **涉及数据对象**：挂单信息、农产品信息、库存信息
- **输出结果**：挂单信息发布，采购商可见，超时自动下架
- **闭环检查**：完整
- **来源/依据**：用户明确

### 场景 2：采购商下单交易

- **场景目标**：采购商筛选挂单并完成下单，保证金冻结
- **参与角色**：采购商（买方）、商户（卖方）、平台系统
- **触发条件**：采购商有采购需求，浏览到满足条件的挂单
- **前置条件**：采购商已完成主体准入、支付账户绑定、保证金账户有足够余额
- **核心流程**：
  1. 采购商通过多维度筛选（品种/规格/价格/产地）查找挂单
  2. 查看挂单详情及溯源信息，选择撮合方式（自主/平台匹配/批量）
  3. 提交下单申请
  4. 平台生成标准化电子交易订单，双方在线确认
  5. 平台自动冻结双方对应保证金
  6. 订单生效，进入交割准备阶段
- **分支流程**：订单异议修改、撮合方式选择
- **异常流程**：库存不足、保证金不足、挂单超时
- **涉及功能**：挂单查询、撮合匹配、下单操作、保证金冻结
- **涉及页面**：挂单列表页、挂单详情页、下单确认页、订单列表页
- **涉及数据对象**：交易订单、保证金记录
- **输出结果**：订单生效，保证金冻结，双方收到消息提醒
- **闭环检查**：完整
- **来源/依据**：用户明确

### 场景 3：农产品交割验收

- **场景目标**：买卖双方完成实物交割，确认验收结果
- **参与角色**：商户（卖方）、采购商（买方）、平台监督（模拟）
- **触发条件**：订单生效后，交割时间到达
- **前置条件**：卖方已完成货物准备和溯源二维码粘贴；买方已准备货款和验收人员
- **核心流程**：
  1. 卖方按订单要求准备货物，上传交割准备凭证
  2. 卖方将农产品送达指定交割地点
  3. 买方到场验收，扫描溯源二维码核对信息
  4. 提交验收结果（合格/不合格）
  5. 验收合格：双方在线签字确认，触发货款结算流程
  6. 验收不合格：买方提交异议及证据，平台24小时内介入处理
- **分支流程**：验收不合格 → 纠纷处理流程
- **异常流程**：交割超时、验收异议、证据不足
- **涉及功能**：交割准备、扫码核对、验收确认、异议提交、纠纷处理
- **涉及页面**：交割准备页、验收确认页、订单详情页、纠纷处理页
- **涉及数据对象**：交割记录、验收结果、异议记录
- **输出结果**：交割确认单生成，溯源信息完善，进入结算流程或异常处理流程
- **闭环检查**：完整
- **来源/依据**：用户明确

### 场景 4：全流程溯源查询

- **场景目标**：消费者/采购商/监管人员查询农产品全流程溯源信息
- **参与角色**：消费者/采购商/监管人员
- **触发条件**：需要了解农产品来源、质量和流转过程
- **前置条件**：溯源信息已录入并审核通过
- **核心流程**：
  1. 扫描农产品包装溯源二维码，或在平台输入溯源码/订单号
  2. 系统展示全环节溯源信息（产地/加工/仓储/运输/交易/交割）
  3. 可查看检测报告、交易记录、验收记录
  4. 支持按环节/时间/品种/主体多维度筛选
  5. 支持导出溯源记录
- **分支流程**：溯源码无效、溯源信息不完整
- **异常流程**：溯源码不存在、信息缺失预警
- **涉及功能**：二维码解析、溯源信息查询、多维度筛选、导出打印
- **涉及页面**：溯源查询页（移动端/PC端）、微信小程序溯源页、大屏溯源展示
- **涉及数据对象**：溯源档案、农产品批次、流转记录
- **输出结果**：完整溯源档案展示，数据可信、不可篡改（区块链模拟）
- **闭环检查**：完整
- **来源/依据**：用户明确

### 场景 5：资金结算与对账

- **场景目标**：完成交割后的货款划转和保证金退还
- **参与角色**：采购商（买方）、商户（卖方）、平台结算系统
- **触发条件**：交割验收合格，双方签字确认
- **前置条件**：买方账户有足够资金；交易双方无未解决纠纷
- **核心流程**：
  1. 平台通知买方支付货款
  2. 买方通过支持渠道（微信/支付宝/银行）支付
  3. 货款存入第三方监管账户（模拟）
  4. 平台核对无误，24小时内扣除0.5%~1%手续费后划转至卖方
  5. 平台自动解冻双方保证金
  6. 生成标准化对账单，双方在线核对，支持导出
  7. 卖方开具发票并上传平台
- **分支流程**：发票上传、对账异议
- **异常流程**：支付失败、结算异常、发票缺失
- **涉及功能**：货款支付、保证金解冻、手续费扣除、对账生成、发票管理
- **涉及页面**：支付页面、对账单页、发票管理页
- **涉及数据对象**：资金流水、对账单、发票记录
- **输出结果**：货款划转完成，保证金退还，对账单生成，凭证留存≥3年
- **闭环检查**：完整
- **来源/依据**：用户明确

### 场景 6：监管大屏实时监管

- **场景目标**：监管人员通过大屏实时监控市场交易和溯源情况
- **参与角色**：监管人员、平台系统
- **触发条件**：监管人员登录大屏端，或系统触发异常预警
- **前置条件**：监管人员已获得授权账号
- **核心流程**：
  1. 公众可查看基础数据（交易概况/行情走势/溯源动态）
  2. 监管人员登录后切换视图，查看详细数据和异常预警
  3. 点击异常数据卡片查看明细
  4. 发送监管指令（违规查处、品种管控等）
  5. 平台执行后反馈结果，形成监管-执行-反馈闭环
- **分支流程**：监管指令下达、预警处理反馈
- **异常流程**：数据异常、预警误报
- **涉及功能**：数据可视化、实时刷新、异常预警、监管指令
- **涉及页面**：监管大屏首页、交易详情页、溯源详情页、预警列表页、指令下发页
- **涉及数据对象**：交易统计、溯源统计、预警记录、监管指令
- **输出结果**：监管指令执行，异常得到及时处置
- **闭环检查**：完整
- **来源/依据**：用户明确

### 场景 7：主体准入审核

- **场景目标**：审核新商户/采购商资质，开通交易权限
- **参与角色**：申请主体、平台运营人员
- **触发条件**：主体申请进入平台交易
- **前置条件**：申请主体已准备资质材料（营业执照、食品经营许可证等）
- **核心流程**：
  1. 主体提交注册申请，上传资质材料
  2. 平台运营人员严格审核
  3. 审核通过：开通交易/服务权限，完成账户开户和支付/溯源账户绑定
  4. 审核失败：反馈原因，引导补充材料重新申请
- **分支流程**：资质补充、重新申请
- **异常流程**：资质造假、资质过期
- **涉及功能**：注册申请、资质上传、审核管理、账户开通、权限配置
- **涉及页面**：注册申请页、资质上传页、审核列表页、审核详情页、账户管理页
- **涉及数据对象**：主体信息、资质材料、审核记录
- **输出结果**：主体获得交易权限，可进行挂单/下单操作
- **闭环检查**：完整
- **来源/依据**：用户明确

| 表格 | 使用Element Plus Table组件，支持分页、排序、筛选 | 列表页数据展示 |
| 表单 | 使用Element Plus Form组件，支持校验、联动 | 新增/编辑页面 |
| 筛选 | 顶部筛选栏+重置按钮，支持多条件组合 | 列表页 |
| 详情 | 信息卡片分组展示，左图右文或上表下详情 | 详情页 |
| 弹窗 | 用于二次确认、快捷操作、详情查看 | 各类操作 |
| 抽屉 | 用于表单填写、详情查看、列表筛选 | 侧边栏操作 |

| 操作按钮 | 主要操作放右侧，次要操作放左侧或更多按钮中 | 表格行操作、页面底部 |
| 异常与空状态 | 统一使用插图+文案+操作按钮的组合 | 无数据、无权限、加载失败 |

### 5.5 权限与数据规则

| 规则类型 | 规则说明 | 适用角色/模块 |
| --- | --- | --- |
| 角色权限 | 基于RBAC模型，角色包含菜单权限和操作权限 | 所有角色 |
| 菜单权限 | 根据角色配置菜单显隐，超级管理员可见全部 | 所有模块 |
| 按钮权限 | 根据角色配置按钮显隐，如新增、编辑、删除 | 所有模块 |
| 数据权限 | 商户/采购商只能查看本人数据；运营/监管可查看全部 | 交易模块、溯源模块 |
| 字段权限 | 敏感字段（手机号、身份证号、银行卡号）脱敏展示 | 所有涉及敏感字段的页面 |
| 日志留痕 | 记录所有敏感操作（溯源修改/删除、资金操作、审核）日志 | 所有模块 |
